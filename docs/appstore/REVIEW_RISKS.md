# Likely App Review risks and mitigations

Checked against the [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) as fetched 2026-10-28 (Apple edits them regularly; re-read before submitting). This is analysis, not a guarantee of approval.

| # | Guideline | Risk | Mitigation |
|---|---|---|---|
| 1 | **2.1 App Completeness**: "include demo account info (and turn on your back-end service!)" | Low now: no feature needs an account. Sync is optional, off by default and uses a server the user supplies; there is no back end of the developer. The remaining risk is a reviewer without an EPUB. | No sign-in required, no demo account (leave "Sign-in required" unticked). The notes explain how to import a public-domain EPUB via Files and attach one or link one (`REVIEW_NOTES.md`). State that sync is optional and not needed for review. |
| 2 | **2.1** | Watch app needs the iPhone app opened once and a paired watch; a reviewer may think the watch app is "empty". | Said in the notes. Both apps show empty states that say what to do (iPhone "No Books" with *Import EPUB*; "No Apple Watch" / "not installed on the watch" states; watch "No Books"). No sample book ships in the release build (the one in `UITestingSupport.swift` is Debug-only); bundling one is an owner option. |
| 3 | **4.2 Minimum Functionality**: app must be "useful, unique, or app-like" and not a repackaged website | A "simple EPUB reader" can be questioned, especially a watch app. | It is a native app with parsing, typography controls, dictionary and background progress sync, which is more than a wrapper. List these concrete features in the description and notes. 4.2.3(i) says the app should work on its own without another app: the watch app declares `WKRunsIndependentlyOfCompanionApp`, so say it works standalone once books are loaded. |
| 4 | **5.1.1(i) Privacy policy** | Policy URL must be in App Store Connect **and within the app**. | Done in code on PR #20: Settings › About › Privacy Policy / Support (`iOSApp/Support/AppLinks.swift`). Its URLs are still `https://example.com/...`: set them to `https://folito.app/privacy.html` and `.../support.html` before the build you submit, and enter the same privacy URL in App Store Connect. Policy re-checked against `docs/PRIVACY_DATA_MAP.md`. |
| 5 | **5.1.1(v) Account sign-in / account deletion** | Resolved by PR #18: the "Create account" action was removed; the app only signs in to an account that already exists on the user's own sync server (created there, e.g. in KOReader), so it "supports account creation" nowhere and in-app deletion is not required. Sync is optional and users can *Turn Off Sync and Remove Login* (removes it from iPhone and watch). | Keep it that way: do not reintroduce account creation (KOSync has no deletion endpoint). Mention in the notes that there is no account creation. Note: `ReaderCore` still contains `KOSyncClient.createUser()` (used only by tests/the watch coordinator API, no UI); harmless, but `docs/PRIVACY_DATA_MAP.md` still lists `POST /users/create` as used by the iPhone app and should be corrected there. |
| 6 | **5.1.1/5.1.2 data use and App Privacy accuracy** | A mismatch between the nutrition label, privacy manifest and real behaviour is a classic rejection. | `APP_PRIVACY.md` and `docs/PRIVACY_DATA_MAP.md` must agree (Search History declared; no tracking). Re-audit whenever networking code changes. |
| 7 | **5.2.1 Intellectual property** (no third-party trademarks or misleading metadata) and **5.2** generally | Naming KOReader/Readest could look like affiliation or endorsement; using their logos or UI is infringement. | Nominative use only: name them in the description solely to say the protocol is compatible ("KOReader Sync protocol, as used by KOReader and Readest"); never in the app name, subtitle, keywords or screenshots; no logos; keep the "not affiliated" sentence. Do not use "Kindle", "Kobo" etc. Fonts: only system fonts are used. Dictionary content: Wiktionary is CC BY-SA; keep a visible attribution in the app (the definitions come from Wiktionary) if you can; mention it in the notes. |
| 8 | **5.2.5 Apple products** | Using Apple watch/iPhone imagery in the icon or screenshots. | Icon must be original; no Apple logos; device frames only as allowed in Apple's marketing resources. |
| 9 | **4.0 Design** and HIG | Small touch targets, clipped text with large Dynamic Type, missing empty states, or an unlocalised UI. | PR #20 did a HIG/accessibility pass (VoiceOver, Dynamic Type, contrast, empty states) with an automated `performAccessibilityAudit` UI test (`docs/ACCESSIBILITY.md`), not yet run on a device. UI strings are English only while a Spanish description is offered: the Spanish description says the interface is in English; or localise first. |
| 10 | **4.8 Login services** | None expected: there is no third-party social login. | n/a (4.8 applies only to apps using third-party or social login for a primary account). |
| 11 | **ATS / network** | `NSAllowsLocalNetworking` plus the local-network prompt may be questioned. | Explain in notes: plain `http://` works only for the user's own LAN server; all internet traffic is HTTPS. No `NSAllowsArbitraryLoads`. |
| 12 | **Beta review (TestFlight external)** | External testing triggers the same review of the first build. | Reuse `REVIEW_NOTES.md` for "Beta App Review Information". |
| 13 | **Content rights** | Users import their own books; the app has no DRM support and ships no copyrighted content. | Answer "does your app contain, show or access third-party content" accurately in App Store Connect (it displays user-imported files and Wiktionary definitions) and keep screenshots to public-domain text. |

## Pre-submission checklist

* [ ] Review notes filled; sample EPUB attached or linked; "Sign-in required" unticked (no demo account).
* [ ] Site published at `https://folito.app/`, contact placeholders replaced, `AppLinks` URLs set to it in the submitted build.
* [ ] App Privacy answers entered; match `docs/PRIVACY_DATA_MAP.md` and the privacy manifests.
* [ ] Accessibility Nutrition Labels declared only after the checks in `ACCESSIBILITY_LABELS.md`.
* [ ] Export compliance key present in the build.
* [ ] Screenshots at valid sizes (`SCREENSHOTS.md`).
* [ ] Names KOReader/Readest only in the compatibility sentence.
* [ ] Build tested on a real iPhone and watch via TestFlight (cold install, import, offline reading, optional sync on/off).
